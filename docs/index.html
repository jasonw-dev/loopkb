loopkb

知識庫不是倉庫，
是一個會自我維護的迴圈

純 Markdown 的 Obsidian vault + git + AI agent。 人只負責丟進去，分類、整理、連結、除舊——agent 的迴圈每週做。

Obsidian 相容 git 原生 規則會學習 Claude Code / Codex / 任何 agent

Your part

人只做三件事

貢獻的成本被刻意壓到最低——格式、分類、歸檔都不是你的工作。

① _inbox/

隨手丟

任何筆記、連結、逐字稿丟進 _inbox/，commit + push。格式不拘。

② kb-save

順口存

剛跟 AI 解完問題？在對話裡說一句「kb-save」，agent 萃取、分類、存檔。

③ kb-loop

每週跑一圈

跑一次 loop，然後讀 _meta/digest.md（兩分鐘）。不同意的動作 git revert 即可。

The loop

Agent 每一圈做什麼

無狀態設計：任何人、任何機器、任何時間都能跑；中斷了下一圈自然接手。

00 LEASE上鎖

同時只有一圈在跑

01 TRIAGE歸檔

清空 inbox：判型態、套模板、入資料夾

02 REFINE精煉

補連結、合併重複、複查最舊筆記

03 REFLECT反省

從人類修正中歸納，提議改規則

04 LINT健檢

lint.py 機械檢查，agent 修復

寫完 digest → 下週再來一圈
Trust ladder

每篇筆記帶著信任等級

讀的時候（人或 agent）優先信任高等級——因為 evergreen 是人背書的，不是 agent 自己蓋章； 兩篇講法互相衝突時不會默默選一邊，agent 會告訴你並把衝突丟回 loop 處理。

Loop engineering

規則會學習：你的修正就是訓練訊號

不用寫報告、不用開會檢討——直接改，系統自己學。

1

Agent 分類

依 _meta/ 的規則歸檔，commit 帶 [kb-loop] 記號。

2

人直接修正

分錯就搬走、不同意就 revert——普通 commit，不需要任何特殊格式。

3

Reflect 歸納

下一圈從 git 歷史認出「人推翻了 agent」，同類修正 ≥ 2 次就成為 pattern。

4

規則更新

更新分類規則——autonomous 模式直接生效並列入 digest，reviewed 模式開 MR 等你批。 規則寫進 instance 設定檔（不是框架檔），所以之後拉模板更新也不會被蓋掉；同樣的錯不再犯，分類越用越準。

Governance

兩種治理模式

在 _meta/instance.md 一行切換。安全底線相同：git 歷史讓一切可回溯。

預設autonomous

事後可撤

agent 一切直接 commit，風險動作逐條列進 digest。 人每週讀兩分鐘，不同意就 revert。人不在關鍵路徑上。

reviewed

事前審批

破壞性動作與規則變更先開 merge request，人批准才落地。 給還沒建立信任的團隊。

Get started

怎麼開始用

兩種角色：建立者做步驟 1（每團隊一次）；成員做步驟 2–3（每人每台機器一次）。 走 Claude Code 或 Codex CLI 的路徑不需要自己 git clone——入口由工具安裝，vault 由 kb-setup 代勞； 其他 agent 走手動路徑，那條路徑要自己 clone。

建立 vault（每個團隊一次）
從 loopkb template 按 「Use this template」開一個新 repo，然後照 repo 裡 GETTING-STARTED 的 checklist 填好 _meta/instance.md（語言、知識範圍、tag 字彙、治理模式）。 做完把 repo 網址發給團隊，並給每個人 repo 的 write access （autonomous 模式下，大家都要能直接 push）。
裝入口（每人一次，全域生效，依你用的 agent 擇一）
Claude Code — 裝 plugin： 
/plugin marketplace add jasonw-dev/loopkb
/plugin install loopkb@loopkb
Codex CLI — 複製 vault 內 integrations/codex/skills/ 的四個 skill 到 ~/.agents/skills/。
其他 agent — 走 GETTING-STARTED 的手動路徑（AGENTS.md 為入口）。
加入 vault（每人每台機器一次）
對 Claude Code 說一句，把網址換成步驟 1 產生的 repo 網址： 
kb-setup https://gitlab.example.com/team/team-kb.git
它會自動 clone、驗證、設定好這台機器。
（選配）同一台機器用多個 vault
同一台機器可以同時用多個 vault（公司知識庫 + 個人第二大腦）： 入口只裝一次，每個 vault 各說一次 kb-setup 即可，互不干擾 （vault 的 repo 名要彼此不同）。
（選配）接線專案 repo
在專案的 CLAUDE.md 加一小段，之後該專案的 agent 遇到問題會先查知識庫。 範本在 vault 的 kb-search skill 裡。
Anatomy

Vault 長什麼樣

全部是 Markdown。Obsidian 打開就能讀，git 就是同步與履歷。

vault/
├── _inbox/            ← 丟就對了，loop 會分類
├── scripts/           ← lint.py（schema 檢查）、lease.py（併發鎖）、
│                        verify_digest.py（digest 有沒有漏報高風險動作）
├── _meta/             ← 規則（taxonomy、loop）、instance 設定、digest
├── troubleshooting/   ← 症狀 → 原因 → 解法
├── decisions/         ← 技術決策記錄
├── guides/            ← how-to
├── references/        ← 外部資料摘要
└── meetings/          ← 會議記錄

型態用資料夾（穩定不變），領域用 tag（封閉字彙——由 instance 宣告、靠修正迴圈演化，不能隨手發明）——一篇筆記一個家，跨領域靠 tag 與 [[wikilink]]。
